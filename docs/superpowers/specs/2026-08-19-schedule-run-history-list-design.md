# 定时任务运行记录列表与详情切换设计

## 背景

当前定时任务页在选择左侧任务后，会在右侧任务详情中的“运行历史”区域直接展示每条执行记录的完整输出。需求是将该区域调整为运行记录列表：默认显示列表，点击某行“详情”进入该次执行的完整详情，详情页提供“返回”按钮回到当前列表页。

## 目标

- 选择左侧定时任务后，右侧默认显示运行记录列表。
- 保留现有任务标题、编辑/暂停/恢复/立即执行/删除操作和上方 4 个信息卡片。
- 列表包含“结果状态、运行状态、执行时间、操作”四列。
- 状态标签沿用定时任务页已有的颜色和样式。
- 无运行记录时，在表头之后的空数据行居中显示“还没开始执行定时任务”。
- 每页最多显示 20 条，底部提供分页控件。
- 点击“详情”显示当前已有的执行详情内容；点击“返回”恢复列表，并保留当前页。

## 非目标

- 不修改定时任务创建、编辑、暂停、恢复、立即执行、删除或服务端执行逻辑。
- 不增加新的路由体系；列表与执行详情在当前定时任务详情区域内切换。
- 不一次性加载全部历史记录；继续使用现有运行记录游标分页接口。

## 现有上下文

- 页面入口：`src/renderer/pages/Schedules/SchedulesPage.tsx`
- 任务详情：`src/renderer/pages/Schedules/ScheduleTaskDetail.tsx`
- 运行历史：`src/renderer/pages/Schedules/ScheduleRunHistory.tsx`
- 状态文本和时间格式化：`src/renderer/pages/Schedules/schedule-task.types.ts`
- 运行记录状态：`succeeded | failed | skipped | aborted | discarded`
- 服务端运行记录接口已经支持 `limit` 和 `cursor`，客户端已有 `listTaskRuns`。

## 交互设计

### 任务详情默认视图

`ScheduleTaskDetail` 保持现有头部、操作按钮和四个摘要卡片不变。摘要卡片下面显示 `ScheduleRunHistory` 列表视图，列表标题仍为“运行历史”，右侧保留刷新操作。

### 运行记录列表

表格列固定为：

1. **结果状态**：使用 `run.status`，通过现有 `statusLabel` 显示“成功”“失败”“跳过”“中止”“已丢弃”，并使用现有 `schedule-status` 样式。
2. **运行状态**：当 `finishedAt === null` 时显示“运行中”，否则显示“已完成”；分别复用现有的绿色运行中样式和中性已暂停样式，避免引入新的颜色体系。
3. **执行时间**：优先显示 `finishedAt`，没有完成时间时显示 `startedAt`。
4. **操作**：显示文字按钮“详情”。

没有记录时保留列表表头，在表体第一行使用 `colSpan=4` 居中显示“还没开始执行定时任务”。

### 分页

- 请求固定使用 `limit=20`。
- 初次选择任务或刷新时加载第一页。
- 点击“下一页”时使用服务端返回的 `nextCursor` 请求下一页，并替换当前页数据，而不是把数据追加到同一页。
- 客户端保存已访问页对应的 cursor，使“上一页”能够返回；第一页禁用“上一页”，没有 `nextCursor` 时禁用“下一页”。
- 底部显示当前页码和上一页/下一页按钮。列表刷新后回到第一页，详情返回时保留进入详情前的页码。

### 执行详情

- 点击列表行的“详情”后，在运行历史区域显示当前已有的执行详情内容：结果状态、触发方式、执行时间、复制输出、Markdown 输出或错误信息。
- 详情顶部新增“返回”按钮。
- 点击“返回”只切换回列表视图，不重新选择任务，也不改变当前列表页。
- 若刷新或任务切换导致当前详情记录不再可用，则回到列表视图。

## 数据与组件设计

### 组件职责

- `ScheduleTaskDetail`：维护当前选中执行记录和列表/详情视图切换，向运行历史组件传递回调。
- `ScheduleRunHistory`：负责运行记录表格、空状态、刷新、分页和“详情”操作。
- 新增或抽取的执行详情组件：负责现有单条执行详情内容及“返回”按钮，继续复用 Markdown 渲染和复制输出行为。
- `schedule-task.store.ts`：将运行记录请求固定为 20 条，并提供可替换当前页的游标分页数据；任务切换/刷新时重置分页状态。

### 类型约束

不修改共享 `ScheduleTaskRunDto`。运行状态由 `finishedAt` 派生，不向后端增加字段：

```ts
const executionState = run.finishedAt === null ? 'running' : 'completed'
```

分页仍复用现有 `ScheduleTaskRunPageDto` 的 `items` 与 `nextCursor`。

## 样式与可访问性

- 表格沿用 `schedules.css` 的背景、边框、字号、间距和状态徽标变量。
- “详情”“返回”、刷新和分页按钮使用真实 `<button>` 元素，支持键盘操作。
- 表格提供语义化表头；空状态使用合并单元格，确保读屏器可以理解表格结构。
- 在现有响应式断点下将表格设置为可横向滚动或调整列宽，不能破坏移动端布局。

## 验证标准

- 选择已有任务后默认看到运行记录表格和四个原有摘要卡片。
- 有记录时四列内容、状态颜色、详情入口正确显示。
- 无记录时准确显示“还没开始执行定时任务”。
- 超过 20 条时可通过底部分页切换，并支持返回上一页。
- 点击详情显示原执行详情；点击返回回到原列表页。
- 创建、编辑、暂停/恢复、立即执行、删除任务行为不回归。
- 相关 Vitest 测试、类型检查和构建命令通过。
